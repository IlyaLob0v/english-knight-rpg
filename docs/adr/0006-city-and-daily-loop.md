# ADR 0006. Город и ежедневный цикл: экономика в контенте, ремонт по FSRS и последнему ответу

Статус: принято · 2026-10-26

## Решение
- **Экономика — это контент.** Новый файл `content/world/progression.json` со схемой `progression.schema.json`: базовое здоровье и подсказки рыцаря, кривая уровней, награды XP/KP за каждое событие, размер патруля, кулдаун задания, враги патруля, порог и длина ремонта. Валидатор проверяет, что кривая растёт с 0, а враги патруля существуют и не боссы. Файл необязательный: без него клиент берёт `DEFAULT_PROGRESSION`, чтобы старые бандлы продолжали работать.
- **Город строится по треку.** Участок города = шаг трека, здание = `unlocks_building`. Победа над боссом открывает стройку, KP строят здание. Построенное здание хранится по `building_id`, поэтому перестановка модулей или перепривязка здания в треке ничего не ломает: ремонтирует здание тот модуль, который сейчас назначен треком.
- **Две валюты.** XP качает рыцаря (уровень → здоровье), KP тратятся на город. Бонусы зданий (`max_hp`, `hint_charges`, `xp_multiplier`, `kp_multiplier`) действуют, только пока здание целое. Подсказки теперь ограничены: `hints_per_battle` плюс бонус Библиотеки.
- **Патруль и ремонт — сценарные бои** (`Battle` с `script`): фиксированный список заданий из `buildPatrol` (просроченные концепты, слабые первыми, задание не чаще раза в `task_cooldown_days`). Проиграть нельзя, это тренировка; в xAPI они помечены `game_context.mode` = `daily_patrol` или `repair` (+ `building`).
- **Уточнение к документу: что считать «отремонтировано».** Документ определял поломку через вероятность вспомнить ниже 0.8. Но FSRS ставит вероятность около 1 сразу после любого повторения, в том числе неверного, и тогда ошибки «чинили» бы здание. Поэтому: трещина появляется, когда концепт ниже порога; в уже треснувшем здании концепт остаётся трещиной, пока последний ответ по нему неверный. Переход «треснуло → целое» = ремонт: statement `repaired` и награда. Последнее известное состояние хранится в прогрессе (`buildings[id].damaged`), трещины отмечаются перед каждым ответом.
- **Статистика ошибок** считается функцией `errorStats` из `@knight/learning` по журналу попыток. Тот же журнал — источник xAPI `answered`, и тест сверяет число ответов и типы ошибок на экране с отправленными statement'ами.
- **Прогресс v2** добавляет `xp`, `kp`, `buildings`, `patrolDays`; `migrateProgress` поднимает сохранения недели 3 без потерь.
- UI города нарисован в Phaser, меню и экран статистики — в DOM, как задания. React по-прежнему не понадобился (ADR 0005).

## Последствия
- Награды подобраны так, что KP после каждого модуля хватает на его здание (Ратуша 0, Кузница 50, Библиотека 80); баланс уровней и наград правится в `progression.json` после плейтеста.
- «День» — локальная дата устройства игрока. Перевод часов может дать лишний патруль; для MVP это приемлемо.
- Арт по-прежнему заглушки: здания — фигуры, поломка — тёмный цвет и красные трещины.
