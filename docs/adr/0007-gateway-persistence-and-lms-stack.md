# ADR 0007. Шлюз на Postgres и локальный стенд LMS

Статус: принято · 2026-10-26

## Контекст
Неделя 5: шлюз должен переживать перезапуск, оценки — сбои LMS, записи xAPI — сбои LRS и офлайн клиента. Интеграцию с LMS проверяем на настоящем Moodle, а не на моках, потому что ошибки LTI всплывают только на живой платформе (адреса, ключи, права на сервисы).

## Решение
- **Postgres через `pg`**, без ORM. Схема — нумерованные SQL-файлы в `apps/server/migrations/`, применяются при старте, каждый один раз (таблица `schema_migrations`). Уже выпущенный файл не правится, изменение схемы — новый файл.
- **Хранилища за теми же интерфейсами**, что были в памяти: `IdentityStore`, `LoginStates`, `ScoreStore`, `OutboxStore` (xAPI), новые `GradeStore` и `ProgressStore`. Без `DATABASE_URL` шлюз работает на памяти (для `pnpm dev:server` и тестов), в `NODE_ENV=production` `DATABASE_URL` обязателен. Каждая запись — один SQL-оператор, транзакции не нужны.
- **Очередь оценок AGS** (`grade_outbox`). Результат модуля сначала записывается, потом отправляется; при ошибке LMS повтор с экспоненциальной задержкой (15 попыток, около суток), затем `failed` для ручного разбора. Ключ — игрок + модуль + контекст LMS, поэтому лучший новый балл заменяет ещё не отправленный, а уже принятый LMS балл повторно не шлётся. Ответ `/progress/module-result`: `sent`, `queued`, `not_improved` или `not_lti`.
- **Очередь xAPI** (`xapi_outbox`). У отправленных записей остаётся только id, поэтому повторная отправка из офлайн-очереди клиента отбрасывается ещё до LRS (а LRS и так дедуплицирует по id).
- **Бэкап прогресса** (`player_progress`). Браузер остаётся источником истины, игра не ждёт сети. Клиент шлёт `progress` и карточки FSRS через несколько секунд после сохранения; при запуске берёт серверную копию, если она новее локальной или локальной нет. Между устройствами побеждает последнее сохранение (`saved_at`). Журнал попыток не копируется: подробная история живёт в LRS.
- **OIDC state в Postgres**: запуск не ломается, если шлюз перезапустился между редиректом логина и POST запуска, и работает при нескольких экземплярах шлюза.
- **Локальный стенд** (`compose.yaml`): Postgres 16, Yet SQL LRS (открытый, Apache-2.0, хранит в том же Postgres), Moodle 4.5 LTS (`erseco/alpine-moodle`). Шлюз и клиент запускаются на хосте через pnpm, чтобы правки кода подхватывались без пересборки образов. `docker/moodle/provision.php` идемпотентно регистрирует инструмент LTI 1.3 (сервис оценок с управлением колонками), создаёт курс, ученика, учителя и по активности на модуль трека с `custom module_id`. Колонке каждой активности присваивается `resourceId` = id модуля, поэтому балл попадает в «свою» колонку, даже если игру открыли из другой активности.
- **E2E на настоящем стенде** (`e2e/lms.e2e.ts`, CI `lms-e2e.yml`): Playwright входит в Moodle новым учеником, открывает активность, проходит бои (два офлайн) и босса, проверяет оценку в журнале Moodle (SQL), каждую попытку в LRS ровно один раз, запрос ошибок по концепту и восстановление прогресса во втором браузере.

## Почему не так
- **SCORM/cmi5 вместо LTI** — не меняем: LTI 1.3 + AGS остаётся каналом оценок (ADR 0003), подробности — в LRS.
- **Learning Locker** как LRS — тяжелее (Mongo, Redis, несколько сервисов) и почти не развивается; SQL LRS — один контейнер на Postgres.
- **Шлюз в Docker-образе уже сейчас** — замедлил бы разработку; образ появится вместе с деплоем.
- **LTI Client Side postMessage Storage** — пока не нужен: state и nonce хранятся на сервере, а не в cookie, поэтому блокировка сторонних cookies в iframe не мешает запуску. Слабее только привязка логина к конкретному браузеру; добавим вместе с поддержкой платформ, которые его требуют.

## Последствия
- Балл модуля по-прежнему сообщает клиент. Для школы нужно проверять его на сервере по принятым `answered` боя с боссом — отдельная задача перед подключением учеников.
- Адреса стенда (Moodle на :8080, шлюз на :8787, `host.docker.internal` для JWKS) годятся только для локальной проверки. Для настоящей LMS нужен публичный HTTPS-адрес шлюза и отдельная регистрация инструмента (`docs/lms-setup.md`).
- Автонастройка открывает Moodle запросы на приватные адреса (`curlsecurityblockedhosts` пуст) и выключает почту: это стенд, не продакшен.
