# ADR 0008. Разворот: платформа школы с разделом Moonbridge

Статус: принято · 2026-10-27

## Контекст
Проект больше не однопользовательская RPG про рыцаря. Теперь это платформа онлайн-школы английского (курс A1–A2 для взрослых, пилот январь–февраль 2027, продажи с марта 2027). Moonbridge — отдельный игровой раздел платформы, привязанный к аккаунту ученика: отель Hotel Hello, жители-существа, эпизоды в стиле визуальной новеллы. План работ: [Moonbridge: план работ](https://claude.ai/artifact/7zR1njFm73QxjwycsMDNCJ).

Движок English Knight (схема контента, проверка ответов с типами ошибок, FSRS, xAPI и LRS, шлюз на Postgres) подходит платформе без изменений по сути. Игровой клиент и контент рыцаря не подходят.

## Решение
- **Тот же репозиторий.** Последнее состояние English Knight — тег `english-knight-v0.5` (коммит 3cf7cb0). Пакеты `@knight/*` переименованы в `@moonbridge/*`, класс профиля xAPI — `XapiProfile`, профиль — `moonbridge-v1`. Репозиторий переименован в `moonbridge` (28.10.2026), старые ссылки GitHub перенаправляет.
- **Удалены:** клиент на Phaser (`apps/client`), сквозной тест через Moodle (`e2e/`, `lms-e2e.yml`, он проходил игру рыцаря), схемы и контент рыцаря (треки, здания, враги, сюжет, прогрессия), xAPI-глаголы `built`, `defeated`, `repaired`.
- **Заморожены:** LTI 1.3 + AGS в шлюзе, стенд Moodle в `compose.yaml`. Школа не работает в LMS, но код и юнит-тесты остаются: если платформа когда-нибудь встанет внутрь чужой LMS, канал уже есть.
- **Модель контента v2** (`schema_version: "2.0"`):
  - Платформа: `modules/` — юниты курса (слово `module` в движке и в идентификаторах xAPI осталось, юнит = модуль), `tasks/` — задания юнита, `courses/` — порядок юнитов. Переставить юниты — правка только файла курса; валидатор не даст поставить юнит раньше его `prerequisites`. У юнита вместо `boss_task_count` — `check_task_count` (итоговая проверка юнита), у задания вместо `combat` — необязательный `time_limit_s` для мини-игр на время, `speaker` из задания ушёл в эпизод.
  - Moonbridge (`moonbridge/`, вся папка необязательна): `characters.json` — жители с портретами по эмоциям (`neutral` обязательна, `happy`, `upset`), `places.json` — места отеля; место открывает юнит из `unlocked_by` (`null` — открыто сразу), `episodes/*.json` — эпизоды визуальной новеллы.
- **Эпизод — список шагов**: реплика (`line`), задание (`task`) с ветками `on_correct` / `on_wrong`, конец (`end`). Без явного перехода шаг продолжается следующим, поэтому линейная сцена пишется без единого id-перехода, а ветка добавляется данными, без кода. Валидатор проверяет: все переходы существуют, каждый шаг достижим с начала, из каждого шага достижим конец (петля «ошибся → попробуй ещё» разрешена, тупиковая петля нет), задание принадлежит юниту эпизода, у персонажа есть портрет нужной эмоции, место эпизода уже открыто к его юниту в каждом курсе.
- **Места следуют за курсом.** Место привязано к юниту, а не к позиции в курсе. Если перестановка юнитов открывает место позже эпизода, который в нём идёт, валидатор выдаёт `order.place`.
- **Тесты не зависят от живого курса.** Три юнита A1 рыцаря переехали в `packages/content/test/fixtures/content` вместе с маленьким Moonbridge; на них работают тесты контента, движка и шлюза. `content/` — живой курс Ксении, сейчас в нём пример юнита 1 «Nice to meet you» и эпизод заселения у Rocco.

## Почему не так
- **Новый репозиторий** — две копии движка, в которые пришлось бы нести каждое исправление; English Knight на паузе и сохранён в теге.
- **Эпизод как граф с обязательным `next` у каждого шага** — ровно столько же проверок, но в разы больше ручных id. Порядок в массиве плюс явные переходы только там, где ветка.
- **Привязка мест к юнитам в файле курса** (как здания в треке) — курс общий для платформы, а места есть только в Moonbridge. Платформа без папки `moonbridge/` работает и не знает о ней.
- **Переименовать `module` в `unit` в движке** — переписало бы идентификаторы xAPI, LTI custom `module_id` и колонки Postgres ради слова. Юнит = модуль, это записано здесь.

## Последствия
- Клиента сейчас нет: неделя 3 плана строит оболочку платформы и раздел Moonbridge заново, на DOM. `pnpm dev:server` отдаёт бандл как раньше.
- В движке остались названия из English Knight: `buildPatrol` в `@moonbridge/learning` станет бюро находок на неделе 4, вместе со своим xAPI-глаголом.
- Арт пока не существует: пути портретов и фонов в контенте — договорённость о названиях файлов для иллюстратора, их наличие не проверяется.
