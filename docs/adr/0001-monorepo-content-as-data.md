# ADR 0001. Монорепо на TypeScript, контент как данные

Статус: принято · 2026-10-26

## Контекст
Главное требование: переставлять модули и менять задания без правки кода. Игра должна запускаться в браузере из LMS (LTI 1.3), а одна и та же схема контента нужна в CI, в игре и в REST API.

## Решение
- Монорепо pnpm: `packages/content`, `packages/learning`, `packages/xapi`, `apps/server`, позже `apps/client`. Пакеты экспортируют исходники TS напрямую, без шага сборки: проще, пока у нас нет публикации пакетов.
- Контент в `content/` как JSON, по одной ответственности на файл: модуль, задания модуля, трек, мир, таксономия. Модуль не знает своего места в сюжете и своего здания: это знает трек.
- JSON Schema (draft 2020-12, Ajv) проверяет каждый файл, а второй проход проверяет связи между файлами: ссылки на концепты, модули, здания, боссов и типы ошибок, циклы в `prerequisites`, порядок трека относительно `prerequisites`, дубли id, согласованность ответов (`accepted` не пересекается с `known_errors`, `order_words` собирается из токенов).
- Сборка выдаёт один бандл с хешем содержимого: клиент и сервер работают с бандлом, а не с файлами.

## Последствия
- Любая правка курса — это PR в `content/`, CI её проверяет до того, как она попадёт в игру.
- Изменение схемы требует повышения `schema_version` и миграции; типы в `packages/content/src/types.ts` правятся вместе со схемой.
- Когда появятся методисты без git, headless CMS сможет писать те же JSON и прогонять тот же валидатор (`PUT /content/source`).
