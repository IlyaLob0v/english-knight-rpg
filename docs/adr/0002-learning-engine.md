# ADR 0002. Учебный движок: FSRS на концептах, оценка из попытки, цепочка классификации

Статус: принято · 2026-10-26

## Решение
- **FSRS через `ts-fsrs` (5.x)**, одна карточка на концепт, а не на задание. Версия алгоритма и целевая вероятность хранятся рядом с каждой карточкой (`StoredConceptCard.scheduler`), чтобы при обновлении библиотеки было видно, чем планировалась карточка.
- **Оценка FSRS выводится автоматически**: ошибка → Again; опечатка, подсказка или медленный ответ (последняя четверть лимита времени или в 1.5 раза дольше медианы игрока) → Hard; быстрее медианы → Easy; иначе Good. Опечатка не Again: грамматика верна.
- **Классификация ответа** — цепочка, первое совпадение побеждает: `accepted` → `known_errors` автора → опечатка → `unclassified`.
- **Уточнение к документу**: допуск опечатки зависит от длины ответа (≤3 символов — 0, ≤6 — 1, иначе 2), а расстояние считается с перестановкой соседних букв как одной правкой («wnet» → «went» = 1). Иначе «a» вместо «an» засчитывалось бы как опечатка, хотя это и есть проверяемая грамматика. Для `choice` и `order_words` опечаток не бывает.
- Движок не зависит от Phaser и ничего не рисует: `LearningEngine.submit()` возвращает результат проверки, оценку, обновлённую карточку, запись журнала и xAPI-statement.
- Статистика ошибок строится из того же журнала попыток, из которого строятся xAPI-записи, поэтому экран статистики и LRS не расходятся.

## Последствия
- Короткие этапы обучения FSRS (минуты) включены: в боссе один концепт может повторяться несколько раз за бой. Если это сделает интервалы слишком короткими, агрегируем попытки по концепту за бой — решение после плейтеста.
- Параметры FSRS по умолчанию; оптимизация по своей истории — после нескольких сотен повторений.
