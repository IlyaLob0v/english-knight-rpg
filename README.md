# Knight of Words

Однопользовательская фэнтези-RPG для изучения английского: рыцарь побеждает врагов заданиями, отстраивает город модулями и «ремонтирует» здания интервальным повторением (FSRS). Архитектура и MVP-план: [Knight of Words: архитектура и MVP-план](https://claude.ai/artifact/UW5MMKcfwFNka3K2XvEszA).

Главное правило репозитория: **контент живёт отдельно от движка.** Модули, задания, порядок прохождения и привязка к зданиям лежат в `content/` как JSON со схемой; ни один пакет с кодом не содержит заданий.

## Структура

```
content/                 данные курса (правишь это, а не код)
  taxonomy/errors.json   словарь типов ошибок
  modules/*.json         модуль: тема, концепты (карточки FSRS), пул заданий, порог освоения
  tasks/*.json           задания модуля (choice, gap_fill, transform, order_words) с known_errors
  tracks/main.json       порядок модулей, главы, какое здание открывает модуль, враги и босс шага
  story/*.json           сюжетные сцены (английский текст + перевод), трек ссылается на них по story_id
  world/*.json           здания, враги и правила прогрессии (progression.json: XP, уровни, KP, патруль, ремонт)
packages/
  content/   @knight/content   JSON Schema, типы, валидатор (ссылки, циклы, дубли), сборка бандла
  learning/  @knight/learning  проверка ответа, классификатор ошибок, FSRS на концептах, патруль, журнал
  xapi/      @knight/xapi      профиль knight-v1, builder statement'ов, клиент LRS, outbox с повторами
apps/
  client/    @knight/client    игра на Phaser 3: город, карта, бои, патруль, ремонт, статистика; задания рисуются по type, текст только из бандла
  server/    @knight/server    шлюз: Content API, приём xAPI → LRS, LTI 1.3 (OIDC-запуск, AGS)
docs/adr/                       архитектурные решения
```

## Команды

```bash
pnpm install
pnpm content:validate   # проверить контент (то же самое делает CI)
pnpm content:bundle     # собрать dist/content-bundle.json
pnpm test               # все тесты
pnpm typecheck
pnpm check            # всё, что проверяет CI, одной командой
pnpm dev:server         # шлюз на http://localhost:8787 (настройки: apps/server/.env.example)
pnpm dev:client         # игра на http://localhost:5173 (шлюз должен быть запущен: клиент берёт контент из него)
pnpm build:client       # статическая сборка в apps/client/dist
pnpm client:no-content  # CI-проверка: в коде клиента нет ни одной фразы из заданий и сюжета
```

## Как играть

Запусти `pnpm dev:server` и `pnpm dev:client` в двух терминалах и открой http://localhost:5173. Шаги трека — точки на карте, открываются по порядку. В каждой точке сначала обычные бои (враги из `encounters` шага), после `wins_before_boss` побед открывается босс. Каждый ход боя — задание из пула модуля: верный ответ бьёт врага на `combat.damage`, ошибка — удар врага и разбор с правильной формой и фидбеком автора, опечатка — скользящий удар. Босс — итоговая проверка модуля: нужно `ceil(boss_task_count × pass_score)` верных ответов, и бой заканчивается, как только это достигнуто или стало недостижимым. Результат уходит в xAPI (`passed`/`failed`) и в шлюз для журнала LMS.

Игра открывается в **городе**. Это центр ежедневного цикла:

- **Здания.** Каждый шаг трека даёт участок в городе под здание из `unlocks_building`. Победа над боссом модуля открывает стройку, здание строится за `cost_kp` и даёт бонус (`bonus` в `world/buildings.json`: здоровье, подсказки, множитель XP или KP).
- **XP и уровень.** XP дают верные ответы (× `difficulty` задания), победы, первый босс модуля, патруль и ремонт. Уровень растёт по кривой `levels.xp_to_reach` и добавляет здоровье.
- **KP** (очки королевства) идут на стройку: за победы, первого босса, патруль и ремонт.
- **Дневной патруль** — 12 заданий (`patrol.size`) по концептам, которые FSRS считает просроченными, самые слабые первыми; одно задание не повторяется чаще раза в 3 дня (`task_cooldown_days`). Награда за патруль раз в сутки, город считает дни на этой неделе и серию.
- **Ремонт.** Если вероятность вспомнить любой изученный концепт модуля падает ниже `repair.threshold` (0.8), здание трескается и не даёт бонус. Ремонт — короткая сессия по слабым концептам (или патруль); трещина держится, пока последний ответ по концепту неверный. Починка пишет xAPI `repaired` и даёт награду.
- **Статистика ошибок** — топ-5 типов ошибок, концепты с числом ошибок и текущей вероятностью вспомнить, список нераспознанных ответов (что добавить в `known_errors`). Строится из журнала попыток, из тех же записей, что уходят в xAPI; период 7 дней, 30 дней или всё время.

Прогресс, карточки FSRS, журнал попыток и очередь xAPI лежат в IndexedDB браузера (отдельная база на игрока), поэтому игра продолжает работать без сети и досылает всё, когда шлюз снова доступен.

## Как менять курс без кода

- **Переставить модули или отдать здание другому модулю** — правка `content/tracks/main.json`. Валидатор не даст поставить модуль раньше его `prerequisites`.
- **Поменять врагов шага или число боёв до босса** — `encounters` в `content/tracks/main.json`; баланс HP и урона — `content/world/enemies.json` и `combat` в задании.
- **Добавить задание** — запись в `content/tasks/<module>.json` и его id в `tasks` модуля. Убрать id из `tasks` — задание выключено, но не удалено.
- **Поменять баланс** (награды, кривую уровней, длину патруля, порог ремонта, врагов патруля) — `content/world/progression.json`. Без этого файла игра берёт встроенные значения по умолчанию.
- **Разметить новую типичную ошибку** — добавить `known_errors` в задание; тип ошибки должен быть в `taxonomy/errors.json`. Частые ответы `unclassified` из экрана статистики — главный источник таких правок.
- **Не переиспользуй** `task_id` и `concept_id`: по ним живут история xAPI и прогресс FSRS. При правке модуля повышай его `version`.

В VS Code схема подхватывается сама через поле `$schema` в каждом файле: автодополнение и подсветка ошибок прямо в редакторе.

## Интеграции

- **xAPI → LRS**: каждая попытка = statement `answered` с типом ошибки, концептом, временем и игровым контекстом. Actor — псевдонимный `account` (`player_id`), без email. Id statement'а = id попытки, поэтому повторная отправка из офлайн-очереди не создаёт дублей.
- **LTI 1.3**: `/lti/login` (OIDC), `/lti/launch` (проверка id_token), `/.well-known/jwks.json`. Сессия игры передаётся токеном в URL-фрагменте, не cookie, чтобы запуск работал в iframe Safari.
- **AGS**: `/progress/module-result` отправляет в журнал LMS лучший результат за модуль (одна строка журнала на модуль).
