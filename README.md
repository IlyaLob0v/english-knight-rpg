# Moonbridge

Платформа онлайн-школы английского и её игровой раздел Moonbridge. Платформа общая для всех курсов: аккаунт, расписание, домашка, прогресс, кабинет преподавателя. Moonbridge — отдельный раздел под тем же аккаунтом: отель Hotel Hello, жители-существа и эпизоды в стиле визуальной новеллы, где верный и неверный английский ведут к разным сценам. План работ: [Moonbridge: план работ](https://claude.ai/artifact/7zR1njFm73QxjwycsMDNCJ). Как проект вырос из English Knight RPG: [ADR 0008](docs/adr/0008-moonbridge-platform.md), последнее состояние игры про рыцаря — тег `english-knight-v0.5`.

Главное правило репозитория: **контент живёт отдельно от кода.** Юниты, задания, порядок курса, места, персонажи и эпизоды лежат в `content/` как JSON со схемой; ни один пакет с кодом не содержит заданий.

## Структура

```
content/                     живой курс (правишь это, а не код)
  taxonomy/errors.json       словарь типов ошибок
  modules/*.json             юнит курса: тема, концепты (карточки повторения), пул заданий, порог проверки
  tasks/*.json               задания юнита (8 типов, см. ниже) с known_errors
  courses/*.json             порядок юнитов курса
  moonbridge/                раздел Moonbridge (необязателен: без папки платформа работает без него)
    characters.json          жители и их портреты по эмоциям
    places.json              места отеля и юнит, который открывает каждое
    episodes/*.json          эпизоды: реплики, задания с ветками на верный и неверный ответ
  media/                     арт и записи: фоны мест, портреты, аудио для listen_type (шлюз раздаёт их по /content/media/…)
packages/
  content/   @moonbridge/content   JSON Schema, типы, валидатор (ссылки, циклы, ветки эпизодов), сборка бандла
             src/sheet/            курс как таблица .xlsx: выгрузка, загрузка, проверка с ошибками по-русски
             test/fixtures/content замороженный набор из трёх юнитов для тестов движка и шлюза
  learning/  @moonbridge/learning  проверка ответа, классификатор ошибок, FSRS на концептах, режим 1/3/7, журнал попыток
  xapi/      @moonbridge/xapi      профиль moonbridge-v1, builder statement'ов, клиент LRS, outbox с повторами
apps/
  web/       @moonbridge/web       платформа в браузере (PWA): вход и приглашения, «Сегодня» (занятие, домашка), сдача файла, кабинет преподавателя; раздел Moonbridge грузится отдельно по /moonbridge
  server/    @moonbridge/server    шлюз: аккаунты, группы, домашка и файлы, Content API, медиа, приём xAPI → LRS, прогресс, Postgres (migrations/); LTI 1.3 заморожен
e2e/         @moonbridge/e2e       Playwright на экране телефона 390 px: эпизод и смена в Moonbridge; школа от приглашения до файла у преподавателя; репетиция пилота (3 ученика × 5 дней)
compose.yaml, docker/              локальный стенд для разработки: Postgres, LRS (Yet SQL LRS), Moodle 4.5 (заморожен)
Dockerfile, deploy/stand/          стенд для пилота: шлюз, платформа за Caddy с HTTPS, Postgres, LRS (docs/stand.md)
docs/adr/                          архитектурные решения
```

Пока нет арта, плеер рисует вместо портретов и фонов заглушки с именем. Арт подключается без правки кода: файл с путём из `characters.json` или `places.json` кладётся в `content/media/`.

## Команды

```bash
pnpm install
pnpm content:validate   # проверить контент (то же самое делает CI)
pnpm content:bundle     # собрать dist/content-bundle.json
pnpm content:export     # курс в таблицу dist/moonbridge-content.xlsx
pnpm content:import <файл.xlsx | ссылка на Google Таблицу>   # таблицу обратно в content/*.json
pnpm test               # все тесты
pnpm typecheck
pnpm check              # всё, что проверяет CI, одной командой
pnpm dev:server         # шлюз на http://localhost:8787 (настройки: apps/server/.env.example)
pnpm dev:web            # платформа на http://localhost:5173 (вместе со шлюзом)
pnpm e2e                # собрать платформу и пройти все три сценария в Chromium на экране 390 px (скриншоты в e2e/.artifacts/)
pnpm e2e:school         # только школа: преподаватель, приглашение, файл, вход со второго телефона
pnpm e2e:pilot          # репетиция пилота: три ученика пять дней, затем страница метрик

docker compose -f deploy/stand/compose.yaml --env-file deploy/stand/.env up -d --build   # стенд на сервере (docs/stand.md)
pnpm lms:up             # стенд в Docker: Postgres, LRS, Moodle (docs/lms-setup.md)
pnpm lrs:errors to_be.i_am   # ошибки по концепту за неделю из LRS
pnpm lms:down
```

## Курс в таблице

Ксения ведёт курс в Google Таблице и публикует его сама, без Ильи ([ADR 0011](docs/adr/0011-content-sheet-and-stand.md)):

1. «Кабинет преподавателя → Контент курса → Скачать таблицу» — весь курс одним .xlsx: листы «Юниты» (порядок строк = порядок юнитов в курсе), «Понятия», «Задания», «Эпизоды» (строка = шаг), «Места», плюс «Как заполнять» и «Справочник» с выпадающими списками.
2. Таблицу открывают в Google Таблицах и дают доступ «Все, у кого есть ссылка — читатель».
3. Там же, в «Контенте курса», вставляют ссылку (или загружают .xlsx) и жмут «Проверить». Ошибки приходят по-русски с листом и строкой: «Задания, строка 12: тип «выборр» не знаком». Когда ошибок нет, видно, какие юниты новые, изменены или убраны, и появляется «Опубликовать».
4. После публикации ученики получают новый контент при следующем открытии платформы. Юниту, который изменился, шлюз сам поднимает `version`.

Таблица заменяет юниты, задания, эпизоды и места. Таксономия ошибок, персонажи и гости дня остаются в репозитории. Опубликованная версия хранится в Postgres и переживает перезапуск; чтобы перенести её в репозиторий, Илья скачивает таблицу и выполняет `pnpm content:import <файл>`: JSON-файлы перепишутся в том же формате.

Записи для `listen_type` пока не готовы, поэтому без файла в `content/media/audio/` телефон читает первый верный ответ голосом (Web Speech).

## Как менять курс в JSON

- **Переставить юниты** — правка `content/courses/<курс>.json`. Валидатор не даст поставить юнит раньше его `prerequisites`, а места Moonbridge открываются вслед за своими юнитами.
- **Добавить задание** — запись в `content/tasks/<юнит>.json` и его id в `tasks` юнита. Убрать id из `tasks` — задание выключено, но не удалено.
- **Разметить типичную ошибку** — `known_errors` в задании; тип ошибки должен быть в `taxonomy/errors.json`.
- **Написать эпизод** — файл в `content/moonbridge/episodes/`. Шаги идут сверху вниз; у задания можно указать `on_correct` и `on_wrong`, у реплики `next`, если нужно уйти не на следующую строку. Последний шаг — `{ "kind": "end" }`. Валидатор найдёт переход в никуда, шаг, до которого нельзя дойти, петлю без выхода, задание из чужого юнита и эмоцию, для которой у персонажа нет портрета.
- **Выбрать тип задания.** Все типы проверяются автоматически:
  - `choice` — выбор варианта; `gap_fill` — вписать слово в `___`; `transform` — переделать предложение; `order_words` — собрать предложение из слов;
  - `listen_type` — послушать `audio` и напечатать. Опечатка засчитывается как верный ответ, но пишется в журнал как `spelling.typo`;
  - `translate_ru_en` — перевести `source` на английский. Подходит любой вариант из `accepted`, регистр и артикли a/an/the не важны (`ignore_articles: false` это выключает);
  - `translate_en_ru` — выбрать перевод `source` из ровно трёх вариантов;
  - `find_error` — нажать на неверное слово в `tokens`. В `accepted` номер слова с нуля, в `correction` верное слово.

  Опечаткой считается разница в одну букву в словах из 4–6 букв и в две в словах длиннее; слова до 3 букв должны совпасть точно, поэтому «an» вместо «a» остаётся ошибкой артикля. Голос, свободный перевод и сочинение автопроверкой не проверяются: их ученик загружает файлом в домашку на платформе.
- **Открыть новое место** — запись в `content/moonbridge/places.json` с `unlocked_by` = id юнита.
- **Гости дня и бюро находок** — `content/moonbridge/daily.json`. Гость: имя, вид, кто из жителей его встречает (`host`), сколько заданий он приносит (`task_count`, 2–8) и четыре реплики: приход, спасибо, лёгкое огорчение и анонс накануне (`teaser`). Гости приходят по очереди, по одному в день. `lost_items` — вещи, которыми в бюро находок становятся ошибки: одна и та же тема всегда теряет одну и ту же вещь. Задания гостю писать не нужно: он берёт их из уже пройденных учеником юнитов.
- **Не переиспользуй** `task_id` и `concept_id`: по ним живут история xAPI и карточки повторения. При правке юнита повышай его `version`.

В VS Code схема подхватывается сама через поле `$schema` в каждом файле: автодополнение и подсветка ошибок прямо в редакторе.

## Повторение

- **1/3/7** (`RepeatSchedule`): концепт, в котором ученик ошибся в день 0, возвращается на 1-й, 3-й и 7-й день после ошибки. Верный ответ в день повторения продвигает цикл, новая ошибка начинает его заново с этого дня, после третьего повторения концепт уходит из цикла. Дни считаются по московскому календарю, поэтому ошибка в 23:50 вернётся уже утром. Из этого списка собирается бюро находок.
- **FSRS** (`ConceptScheduler`) по-прежнему ведёт карточки концептов и слов.

## Смена в отеле

Раз в день на карте отеля и на главной платформы появляется смена:

1. **Бюро находок.** Сегодняшние ошибки по 1/3/7 приходят вещами, которые гости забыли в отеле. Верный ответ возвращает вещь хозяину и продвигает цикл повторения, неверный оставляет её до следующего дня цикла.
2. **Гость дня** приносит задания только из пройденных юнитов, сначала те, что ученик давно не видел.
3. **Финал**: сколько вещей вернули, как прошёл гость, серия дней и анонс завтрашнего гостя.

Смена укладывается в 15 минут по медианному времени ответа самого ученика: сначала урезаются задания гостя (до двух), потом вещи, лишние вещи ждут завтра. **Серия** считает дни практики и прощает один пропуск; после трёх и больше дней без практики ученика встречают словами «С возвращением», без упрёков.

Офлайн: после первого открытия раздела онлайн страница, код раздела, курс и прогресс лежат на устройстве. Смену можно пройти без сети, ответы уйдут в LRS, когда связь вернётся.

## Школа: аккаунты, группы, домашка

1. **Преподаватель.** Аккаунт заводит тот, кто держит школу ([ADR 0009](docs/adr/0009-accounts-groups-homework-files.md)):
   ```bash
   curl -X POST http://localhost:8787/admin/teachers -H "Authorization: Bearer $ADMIN_TOKEN" \
        -H "Content-Type: application/json" -d '{"name":"Ксения","login":"ksenia","password":"…"}'
   ```
   Преподаватель входит на платформу, открывает «Кабинет преподавателя», создаёт группу с днями, временем и ссылкой на звонок и нажимает «Пригласить ученика».
2. **Ученик** открывает ссылку `/join/<код>` (действует 14 дней), вводит имя, логин и пароль и попадает на «Сегодня»: следующее занятие со ссылкой на звонок и домашка. То же видно на доске в лобби Moonbridge.
3. **Домашка** задаётся группе. Если она сдаётся файлом (запись с диктофона, фото тетради, документ до 50 МБ), ученик загружает его с телефона.
4. **Проверка.** Сданные файлы ждут преподавателя в очереди наверху кабинета: запись и фото открываются прямо там, оценка 1–5 и комментарий сразу видны ученику в домашке. Новая загрузка того же задания снова встаёт в очередь.
5. **Неделя ученика.** В группе у каждого ученика видны дни с практикой, точность с первого раза и самая частая ошибка; по имени открывается еженедельный отчёт (дни, ответы, точность к прошлой неделе, частые ошибки, где занимался, домашка недели). Там же преподаватель задаёт новый пароль, если ученик забыл свой. Ученик видит свою неделю на «Сегодня».
6. **Другой телефон.** Тот же логин и пароль возвращают отель, пройденные эпизоды и график повторений. Гость, который играл до приглашения, при вступлении сохраняет свой прогресс.

Время занятий и сроки домашки — московские.

## Пилот: метрики и сообщения о проблемах

Как провести прогон на друзьях: [docs/friends-run.md](docs/friends-run.md).

- **Метрики пилота.** В кабинете у группы ссылка «Метрики пилота →»: цели из плана (дни с практикой в неделю, активные на 4-й неделе, медиана обязательной сессии, добровольные сессии, вещи из бюро находок, рост точности по типам ошибок), разбивка по неделям и по ученикам, кнопка «Скачать по неделям (.csv)» для еженедельного снимка. Недели считаются от «Начала пилота», которое преподаватель задаёт там же; пока его нет — от недели первого ответа. Всё считается из журнала ответов, определения — в [ADR 0012](docs/adr/0012-pilot-metrics.md) и в блоке «Как считается» на странице.
- **«Сообщить о проблеме».** Внизу «Сегодня» и под картой отеля: ученик пишет, что случилось, шлюз сохраняет текст со страницей и браузером телефона. Преподаватель видит сообщения своей группы на странице метрик, все сообщения — `curl https://<домен>/api/admin/feedback -H "Authorization: Bearer $ADMIN_TOKEN"`.

## Шлюз

- **Content API**: `/content/bundle` (с ETag), `/content/manifest`, `PUT /content/source` (админ-токен) заменяет контент только проверенным.
- **xAPI → LRS**: каждая попытка = statement `answered` с типом ошибки, концептом и временем. Actor — псевдонимный `account`, без email. Id statement'а = id попытки, поэтому повторная отправка из офлайн-очереди не создаёт дублей. Шлюз держит очередь в Postgres и досылает её при сбое LRS.
- **Прогресс**: бэкап прогресса ученика между устройствами.
- **Журнал ответов**: шлюз сохраняет каждый `answered` из приёма xAPI в таблицу `attempts` (повторная отправка из офлайн-очереди не дублирует), отсюда считается кабинет преподавателя без запросов к LRS.
- **Контент из таблицы**: `GET /school/content`, `GET /school/content/sheet` (.xlsx), `POST /school/content/check` и `/publish` (файл .xlsx телом запроса или `{ "url": "<ссылка на Google Таблицу>" }`), только для преподавателей. Версии лежат в `content_versions`.
- **Школа**: `/auth/login` (после 5 неверных паролей к одному логину или 30 с одного адреса за 15 минут — пауза, `429`), `/invites/:code` и `/invites/:code/join`, `/school/dashboard`, группы, приглашения и домашка преподавателя, `PUT /school/homework/:id/submission` (файл до 50 МБ телом запроса), скачивание по ссылке на 5 минут, `/school/review-queue` и оценка, `/school/groups/:id/progress`, `/school/students/:id/report?week=`, сброс пароля, `/school/groups/:id/metrics` и `PUT /school/groups/:id/pilot`, `POST /feedback` и `GET /admin/feedback`. Файлы лежат в бакете S3 (`S3_BUCKET`, на стенде — Yandex Object Storage) или, без него, в `UPLOAD_DIR`.
- **Postgres**: без `DATABASE_URL` шлюз поднимает Postgres в своём процессе (PGlite) и всё забывает при перезапуске; в продакшене база обязательна. Миграции применяются при старте.
- **Стенд**: `Dockerfile` и `deploy/stand/` — Postgres, LRS, шлюз и Caddy с HTTPS на одной машине в российском регионе; пошагово в [docs/stand.md](docs/stand.md).
- **LTI 1.3 и AGS** (заморожено): код и тесты остаются на случай, если платформу понадобится открыть из внешней LMS. Стенд Moodle описан в [docs/lms-setup.md](docs/lms-setup.md).
